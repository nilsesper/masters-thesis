With the scintillation detector and the developed readout system described in the last chapter (sec.\ \ref{sec:Scint}), a dataset of atmospheric muons was recorded. This chapter presents the recorded data and the analysis procedure. Also, all required calibration measurements of the readout system are presented in this chapter, which need to be performed before data can be recorded.

\section{Discriminator threshold calibration}
%\begin{itemize}
%    \item FPGA-internal comparators (on FPGA silicon die) are subject to production uncertainties
%    \item Unfolds in voltage bias on comparator switching point
%    \item Scan input voltage range while keeping other comparator input constant to detemine switching point of comparator (Metastability calibration)
%    \item Account for measured biases when setting thresolds
%\end{itemize}
\label{sec:ScintData-VoltageBias}
The \ac{FPGA}-internal comparators used for discrimination of the analog \ac{SiPM} signals have individual bias voltages (sec.\ \ref{sec:Scint-ReadoutBoard-FPGASampling}). An ideal comparator would switch its output state at the point where both input voltages are equal: $V_+ = V_-$. For the non-ideal comparator, the switching point is shifted by the bias voltage: $V_+ + V_\text{bias} = V_-$. As explained, the bias voltage is expected to be as high as $\pm 35 \;\si{\milli\volt}$ \cite{UltraScale-FPGA-SelectIO-Resources}. As the discriminator threshold lies in the range of $\mathcal{O}(\SI{10}{\milli\volt})$, a calibration of the bias voltage for each individual comparator is essential, before the readout system is ready to record data.
\FloatBarrier
\paragraph{Measurement with function generator}
There are several ways to measure the real switching point of the comparator and extract the bias. The established method is to use a well-defined triangular pulse generated by a function generator for this purpose. By measuring the timestamps of the comparator switching points one can calculate the bias \cite{FPGA-MVT-Xi,FPGA-MVT-Eliseev}. The advantage of this method is that one measures the rising and falling edges of the comparator separately, i.e.\ one can conclude whether the comparator shows a hysteresis effect. However, the conducted measurements indicate no significant hysteresis.
\FloatBarrier
\paragraph{Measurement with comparator metastability}
A novel approach for the measurement of the comparator bias was introduced by our group \cite{MSc-Ehlert}, which eliminates the need for an external function generator. Instead, the method only requires an adjustable voltage source (an \ac{ADC}) at the signal input of the comparator. This significantly reduces the complexity of the calibration setup. In the case of the developed readout board (sec.\ \ref{sec:Scint-ReadoutBoard}), this functionality is already included on the \ac{PCB} itself.
\newline One input of the comparator is set to the desired discriminator threshold voltage: $V_-=V_\text{thres}$. The voltage of the other input is varied in the range $V_+ \in [V_\text{thres}-\SI{50}{\milli\volt},\; V_\text{thres}+\SI{50}{\milli\volt} ]$ with a fine step size. For each step, the count rate of the comparator switching events is measured. This is enabled by counting registers inside the \ac{FPGA} logic which can be read out and reset to zero after changing the voltage level. At the switching point of the comparator, the output is undefined. For an ideal device, one would expect a delta peak. For the real comparator, one would expect a peak in the count rate with a finite width, as electronic noise leads to small fluctuations in the comparator input voltages. By estimating the position of the peak, the bias voltage $V_\text{bias}$ can be estimated. Fig.\ \ref{fig:ScintData-VoltageBias-Scheme} illustrated the described calibration method exploiting the comparator metastability.
\begin{figure}[htb]
    \centering
    \includegraphics[width=0.8\textwidth]{Scint-VoltageBias-Scheme.pdf}
    \caption{Illustration of the described metastability calibration method to measure the comparator bias voltage \cite[adapted]{MSc-Ehlert}.}
    \label{fig:ScintData-VoltageBias-Scheme}
\end{figure}
\FloatBarrier
\paragraph{Observed bias voltages}
The voltage scans are performed for all input channels of the \ac{FPGA} and the switching rate histogram is analyzed. Fig.\ \ref{fig:ScintData-VoltageBias-SwitchingCount} shows an example histogram of the switching rate depending on the applied \ac{DAC} voltage. The step size is limited by the accuracy of the used \ac{DAC} to \SI{2.5}{\milli\volt}. The count rate exhibits the expected shape with a clear peak. It should be noted that the peak position is not equal to the threshold voltage applied to the other input of the comparator, indicating a non-zero bias voltage.
\begin{figure}[htb]
    \centering % presented histogram: ca3 zynq51 input4 step0
    \includegraphics[width=0.7\textwidth]{scint_thres_calib/single_count_hist.pdf}
    \caption{Example switching rate histogram for a single comparator of the \ac{FPGA}. The weighted mean of the distribution is marked in red. Initially it deviates from the threshold voltage (gray) applied to the other input of the comparator, because of the nonzero bias voltage.}
    \label{fig:ScintData-VoltageBias-SwitchingCount}
\end{figure}
\newline The bias voltage is calculated as difference between the switching rate peak position $\left\langle V_\text{DAC} \right\rangle$ and the expected peak position $V_\text{thres}$:
\begin{equation}
    V_\text{bias} = \left\langle V_\text{DAC} \right\rangle - V_\text{thres}.
    \label{eq:Scint-VoltageBias-BiasCalculation}
\end{equation}
 The result for the measured bias voltage for all 32 inputs of a readout board is presented below in fig.\ \ref{fig:ScintData-VoltageBias-CalibResult} with the blue data points. The obtained bias voltages lie in the range \SI{-10}{\milli\volt} to \SI{15}{\milli\volt}, which is compatible with the mentioned maximum range of $\pm 35 \;\si{\milli\volt}$ from the \ac{FPGA} vendor datasheet \cite{UltraScale-FPGA-SelectIO-Resources}. 
\FloatBarrier
\paragraph{Bias voltage correction}
After the measurement, the comparator threshold voltages are adjusted accordingly. To account for the obtained bias voltage, the new threshold voltage is selected as
\begin{equation}
    V_\text{thres,new} = V_\text{thres,initial} - V_\text{bias}.
    \label{fig:ScintData-VoltageBias-NewThresold}
\end{equation}
The procedure is repeated multiple times, in order to iteratively improve the precision of the calibration.
\FloatBarrier
\paragraph{Validation measurement}
After setting the final threshold voltage, the bias voltage is measured one more time to validate the outcome of the calibration. The obtained validation data points are also shown in fig.\ \ref{fig:ScintData-VoltageBias-CalibResult}, with the read data points. As expected, the bias voltage could be mostly removed with this procedure, while few channels show a small remaining offset of $\mathcal{O}(\SI{1}{\milli\volt})$. Repeating the validation measurements after a power-cycle or a longer time does not show significant changes, hinting that the bias voltage is stable in time. However (as described in sec.\ \ref{sec:Scint-ReadoutBoard-FPGASampling}), the measured bias voltages depend on the applied threshold, making it necessary to repeat the calibration after the threshold is changed.

\section{TDC timing calibration}
%\begin{itemize}
%    \item Bank-specific calibration of deserializers on each power-cycle leads to non-deterministic signal delays
%    \item Use simultaneous testpulses to measure these delays
%    \item Use delay module in firmware to correct for these effects already on the device
%    \item Mention ringing of testpulse signal in circuit, but explain that no negative effect on calibration
%\end{itemize}
\label{sec:ScintData-TimingBias}
As explained in sec.\ \ref{sec:Scint-ReadoutFirmware-SamplingTDC}, the \ac{TDC} logic of the readout board is realized in the \ac{FPGA} firmware by utilizing the deserializer primitives of the chip. On startup of the \ac{FPGA}, the deserializers are internally calibrated, individually for each component. This individual calibration leads to non-deterministic time offsets between different groups of inputs. In order to record data with precisely known hit timestamp, it is therefore required to perform a timing calibration, which is discussed in this section.
\FloatBarrier
\paragraph{Simultaneous testpulse generation}
The readout board offers the possibility to transmit simultaneous testpulses to all input channels (sec.\ \ref{fig:Scint-ReadoutBoard-AnalogCircuit}). Similar to the \ac{DT} timing calibration with testpulses (sec.\ \ref{sec:DTData-Testpulse}), it is possible to extract timing offsets between the input channels by measuring the timestamps of the testpulse hits.
\FloatBarrier
\paragraph{Testpulse response} 
The testpulses are issued at a fixed time relative to the beginning of an orbit (which starts at $BX=0$, $TDC=0$). The timestamps of the testpulse-induced hits in all channels is recorded. Once again, one can define the $T_\text{orbit}$ variable, which is the time of testpulse arrival after the beginning of the orbit (cf.\ sec.\ \ref{sec:DTData-Testpulse-Generation}). A histogram of the recorded testpulse hit timestamps for one channel is presented in fig.\ \ref{fig:ScintData-TimingBias-TPTimestamp}. The testpulse timing seems to be very sharp $\mathcal{O}(\SI{1}{\nano\second})$, with only two TDC bins showing entries in the histogram.
\begin{figure}[htb]
    \centering % presented histogram: 
    \includegraphics[width=0.7\textwidth]{scint_timing_calib/single_timing_hist.pdf}
    \caption{Example histogram of testpulse arrival timing for one input channel of the readout board.}
    \label{fig:ScintData-TimingBias-TPTimestamp}
\end{figure}
\newline To quantify the testpulse timing of each channel with one value, the weighted mean $\left\langle T_\text{orbit} \right\rangle$ is calculated and used. The initially recorded testpulse timing for all 64 channels of the two used readout boards is presented in fig.\ \ref{fig:ScintData-TimingBias-CalibResult} with the blue data points. It is evident that there are several groups of inputs which lie closely together in time for each readout board. This behavior is expected, as the \ac{FPGA}-internal calibration of the deserializer units is happening on the scope of so-called I/O banks of the \ac{FPGA}. When mapping the input channels back to these I/O banks of the chip, it becomes evident that the two groups of input channels for each board in the timing diagram correspond to these banks (indicated with different data markers in fig.\ \ref{fig:ScintData-TimingBias-CalibResult}). With each power-cycle of the board, the calibration takes place again, meaning that the timing calibration is required after each startup of the board. The observed timing fluctuation is usually $\lesssim \SI{80}{\tu}$ (\SI{62}{\nano\second}).
\FloatBarrier
\paragraph{Timing correction with delay unit}
In principle, it would be possible to only extract the timing corrections from the measurement and do the actual correction of the recorded data offline. As the \ac{FPGA} firmware features a programmable delay unit for each input channel (sec.\ \ref{sec:Scint-ReadoutFirmware-ProgrammableDelays}), it is even possible to program the delays according to the observed timing differences and perform this correction already "online". The method of determining the delays to be programmed for all input channels is discussed in this section.
\newline Because it is only possible to delay the timing of the input channels, the target timing for all channels has to be selected as the maximum observed timestamp of all channels:
\begin{equation}
    T_\text{orbit,target} = \max \left\{ T_{\text{orbit},i} \; ; \; i=0,...,N_\text{chs} \right\} .
    \label{eq:ScintData-TimingBias-TimingTarget}
\end{equation}
In order to reach the desired timing of each input channel, one needs to subtract the observed testpulse timestamp $\left\langle T_\text{orbit} \right\rangle$ of the respective channel from the target value. For technical reasons, the delay unit in the firmware only allows to set the delay with a granularity of $T_\text{delaystep}=\SI{8}{\tu}$. This of course implies that the timing correction can not be better than this granularity. The delay register value to be programmed for channel $i$ is obtained by division and integer rounding of the target delay:
\begin{equation}
    \texttt{Delay\_Register}(i) = \text{round}\left( \frac{T_\text{orbit,target} - \left\langle T_{\text{orbit},i} \right\rangle}{T_\text{delaystep}} \right) .
    \label{eq:ScintData-TimingBias-DelayRegisterValue}
\end{equation}
\FloatBarrier
\paragraph{Validation measurement}
After setting the proper delay unit values, a validation measurement is performed with the testpulses. The resulting testpulse timing after the "online" timing correction is also presented in fig.\ \ref{fig:ScintData-TimingBias-CalibResult} in red. It is clearly visible that the testpulse response is now aligned within a window of $\approx\SI{8}{\tu}$ which corresponds to the expected accuracy limit of the correction due to the delay unit granularity. Note that the correction is simultaneously applied for the two readout boards, leading to the desired situation where all 64 channels are aligned in time, not only those channels which are connected to the same readout board.

\section{SiPM noise scan}
%\begin{itemize}
%    \item Scan of SiPM rates for different thresolds with developed readout system
%    \item Show resulting curve
%    \item Discuss visible exponential (expected) behavior
%    \item Aliasing effects (too coarse scanning steps) hide expected steps in spectrum
%\end{itemize}
\label{sec:ScintData-Noise}
Before atmospheric muon data is recorded with the system, the setup should be exercised by measuring the \ac{SiPM} noise rates for different discriminator threshold voltages. This is done as a plausibility check of the developed readout system as well as to check that the \acp{SiPM} on the detector are behaving as expected.
\newline Note that this measurement was only performed with one readout board and 32 \acp{SiPM}, and not with the full scintillation detector.
\FloatBarrier
\paragraph{Discriminator threshold range}
In order to measure the \ac{SiPM} rates for different threshold voltage levels, it is first necessary to perform a discriminator threshold calibration (sec.\ \ref{sec:ScintData-VoltageBias}) for each voltage. This is necessary because the comparator bias measured with the calibration procedure is dependent on the selected threshold, as discussed above. After all calibration runs have been completed, the \acp{SiPM} of the scintillator can be connected to the readout board.
\newline The range of discriminator thresholds to be considered for the \ac{SiPM} noise measurement is $\SI{2.5}{\milli\volt}-\SI{32.5}{\milli\volt}$.  The \acp{DAC} which provide the threshold voltage $V_\text{thres}$ have a granularity of \SI{2.5}{\milli\volt}. The common voltage $V_\text{com}$ on the other side of the discriminator circuit is provided with a common \ac{DAC} with the same granularity (sec.\ \ref{sec:Scint-ReadoutBoard-InputCircuitry}).
\FloatBarrier
\paragraph{Rate measurement}
As one expects very high rates for low threshold values and the transmission bandwidth of hits to the backend is limited, the count rate of the inputs is measured directly on the readout board itself, with the counter registers that are also used for the comparator bias calibration (sec.\ \ref{sec:ScintData-VoltageBias}). From the measurement duration and the obtained hit count, it is trivial to calculate the rate present at the input. In this case, the number of hits is recorded for $\SI{10}{\second}$ per \ac{SiPM} and threshold voltage, which already gives a sufficiently high count to have reasonable uncertainties.
\newline Using the counter registers in the \ac{FPGA} firmware for the measurement has the described advantage of not being limited by the data transfer rate to the backend. On the other hand however, the counter register is directly attached to the input block of the firmware. This means that the dead time logic is not yet applied to the counted hits.
\newline As will be discussed in sec.\ \ref{sec:ScintData-Hits-Systematics} in detail, signal reflections and crosstalk are observed in measurements with the readout board. It is clear that these effects have an influence on the measured \ac{SiPM} rate. Since the measurement of the \ac{SiPM} noise spectrum in this section is only envisioned as a plausibility check, and not as a characterization measurement of the \ac{SiPM} device, this is accepted here.
\FloatBarrier
\paragraph{Resulting SiPM rates}
Fig.\ \ref{fig:ScintData-Noise-ScanResult} presents the resulting rates of 29 \acp{SiPM} channels. Three channels had to be excluded from the measurement, because they showed unphysical behavior, which might be related to a defect in the \ac{SiPM} or its preamplifier, or in a defect comparator inside the \ac{FPGA}.
\newline Note that the estimated uncertainties on the rate from the Poisson counting error are negligible, and not even visible in the plot. However, the uncertainty of threshold voltage (on the $x$-axis) is significant, as the granularity of the selectable threshold is relatively large.\footnote{As both the $V_\text{thres}$ and $V_\text{com}$ inputs of the comparator are connected to \acp{DAC} with a granularity of $\Delta V_\text{DAC}=\SI{2.5}{\milli\volt}$, the resulting uncertainty of the effective discrimination thresold $V_\text{thres,eff}=V_\text{thres}-V_\text{com}$ is calculated to be $\sigma_\text{thres,eff}=\sqrt{2\cdot \left( \Delta V_\text{DAC}/\sqrt{12} \right)^2 }\approx \SI{1}{\milli\volt}$. This is almost as large as the measured threshold voltage steps.}
\begin{figure}[htb]
    \centering
    \includegraphics[width=0.7\textwidth]{scint_noise_scan/sipm_rates.pdf}
    \caption{Obtained rates of 29 \acp{SiPM} for different discrimination thresholds in the range $\SI{2.5}{\milli\volt}-\SI{32.5}{\milli\volt}$ presented in a logarithmic plot, measured with one readout board.}
    \label{fig:ScintData-Noise-ScanResult}
\end{figure}
\newline The measured \ac{SiPM} rates show a clearly visible exponentially falling behavior with increasing threshold voltages. Over the measured range with a width of \SI{30}{\milli\volt}, the rate decreases by around four orders of magnitude.
\newline Another observation is the strong fluctuations in rate between individual \acp{SiPM}. There are several cases where different \acp{SiPM} show rate differences of more than one order of magnitude for the same threshold voltage.
\FloatBarrier
\paragraph{Comparison to expectation}
As discussed in sec.\ \ref{sec:Scintillators-SiPMs}, the noise of \acp{SiPM} originates from thermal excitations of electrons in the sensitive region of the device. This noise results in a signal with one \ac{p.e.} amplitude. Due to the non-zero probability $p_\text{cross}>0$ for crosstalk between \ac{GAPD} cells on the \ac{SiPM}, the amplitude of the noise hit can be increased. For $N$ triggered cells, the amplitude increases to $N$ \ac{p.e.}, however the probability for this is suppressed by a factor $\propto \left( p_\text{cross} \right)^N$. Therefore, one expects an exponentially falling distribution of the noise rate with increasing discriminator threshold. In theory, the decrease in count rate is expected to happen in discrete steps, as each step translates to the activation of another discrete \ac{GAPD} cell. Fig.\ \ref{fig:SiPM-NoiseSpectrum} in the theory chapter shows a reference measurement of a \ac{SiPM} noise spectrum.
\newline The expected exponential behavior can be well observed in the noise scan in this thesis, which as presented above (fig.\ \ref{fig:ScintData-Noise-ScanResult}). Since the used frontend board of the \ac{SiPM} has a preamplifier with a conversion factor of $\approx \SI{5}{\milli\volt}$/\ac{p.e.}, which is in the same order of magnitude as the scan steps of \SI{2.5}{\milli\volt}, strong aliasing effects should occur. In the measurement, the discrete steps can not be directly observed, however this should be caused by the expected aliasing.

\label{sec:ScintData-Hits}
In this section, the recorded \ac{SiPM} hit data is presented. The developed readout system (sec.\ \ref{sec:Scint-ReadoutBoard}) is able to successfully receive the signals from the \acp{SiPM} and digitize the hits. \subsection{Observed systematic effects in unbiased dataset}
\label{sec:ScintData-Hits-Systematics}
The observed systematic effects in the \ac{SiPM} hits recorded with the developed readout board, are illustrated and discussed with a small unbiased dataset in this section. This data has no dead time programmed on the \ac{FPGA} (sec.\ \ref{sec:DTData-CellHits-DeadTime}), as this is the most unbiased configuration to record data. The discriminator threshold voltage is set to \SI{25}{\milli\volt}, which corresponds to around 5 \ac{p.e.} with the used frontend board (sec.\ \ref{sec:Scint-Frontend}). More information on the recorded unbiased dataset are presented in tab.\ \ref{tab:ScintData-Unbiased-DatasetInfo}. Note that the size of this dataset is relatively small, however the statistics are high enough to observe the systematic effects.

\paragraph{SiPM occupancies}
In the short recording time of the presented unbiased dataset, already a very high \ac{SiPM} hit count was recorded: In total, the unbiased dataset includes \num{4286627} hits, which corresponds to an average rate per \ac{SiPM} of $(1615.4 \pm 0.8)\;\si{\hertz}$. Given the selected discriminator threshold of 5 \ac{p.e.}, this rate seems unexpectedly high. Potential reasons for this high rate are discussed in the following.
\FloatBarrier
\paragraph{Time distribution of hits}
If one considers the time difference $\Delta T$ between consecutive hits of the same \ac{SiPM} channel, one would expect an exponential distribution. This is due to the fact that the muon signals as well as the thermal noise are random processes which obey Poisson statistics.
\newline Fig.\ \ref{fig:ScintData-Unbiased-Hist-DeltaT-wide} presents the calculated histogram of time differences between \ac{SiPM} hits of the same channel for the unbiased dataset on a relatively broad timescale of $\mathcal{O}(\SI{10}{\milli\second})$. In the plot, the expected constant slope can be observed which represents the exponential distribution in the time difference between hits. Therefore, this behavior is compatible with the expectation.

\end{SCfigure}
\FloatBarrier
\paragraph{Prompt secondary hits}
If one considers a significantly smaller interval for the hit time difference $\Delta T$, of the order $\mathcal{O}(\SI{100}{\nano\second})$, one would naively also expect the exponential distribution. The possibility of after-pulses generated by the \ac{SiPM} (sec.\ \ref{sec:Scintillators-SiPMs}) might lead to an additional contribution to the low time difference bins. The discriminator threshold of around 5 \ac{p.e.} is however relatively high, which should suppress this effect, as the after-pulses generally have lower amplitudes.
\newline Fig.\ \ref{fig:ScintData-Unbiased-Hist-DeltaT-close} presents the measured distribution of hit time differences again for a single \ac{SiPM} in the narrower time range. Instead of the expected exponential slope, a periodic peak structure is visible. The peaks have a distance of roughly \SI{10}{\nano\second} and an approximately exponentially decreasing amplitude towards larger time differences.
\newline It is clear that the observed behavior with frequent secondary hits after a "real" \ac{SiPM} hit is not acceptable for the data taking with the system. These hits will lead to double- or even multiple-counting of a single \ac{SiPM} hit, which then creates fake events and artificially creates a higher detector rate. The high \ac{SiPM} hit rate observed in this dataset might therefore be explained with the observed secondary hits.

    \label{fig:ScintData-Unbiased-Hist-DeltaT-close}

\FloatBarrier
\paragraph{Possible signal reflections}
The observed discrete peak structure can not be explained with after-pulses of the \ac{SiPM}, as this process itself is also random, and therefore continuous. A different hypothesis, which might be able to explain the behavior, are reflections of the \ac{SiPM} signal in the electronics, or related instabilities of the analog input circuitry (sec.\ \ref{fig:Scint-ReadoutBoard-AnalogCircuit}). The discrete peaks would then originate from the finite propagation time between reflections (or the period of induced oscillations in the circuit). The decay of the peak amplitude could also be explained, as the oscillations in the circuit are dampened by the internal resistances.
\newline During the development of the readout board (sec.\ \ref{sec:Scint-ReadoutBoard}), the analog input circuit was carefully planned and even simulated, and no significant oscillations could be observed. However, it is still possible that the observed peak structure in time are caused by this circuit, as the circuit simulation can not model all properties of the complete electronic system.
\newline Due to time constraints, the observed secondary hits in the \ac{SiPM} data could not be investigated in more details as was presented in this section. It is clear that the complete characterization and the potential development of an improved input circuit should be part of the tasks in the future, should the developed readout system be used beyond this thesis.
\FloatBarrier
\paragraph{Proposed countermeasures}
As explained, the re-development of the complete input circuitry was not reasonable in the given time frame of this thesis. As the goal of this work is to demonstrate the synchronization of the developed scintillator readout system with the \ac{DT} chamber (sec.\ \ref{sec:Combined}), it is however necessary to record some data with the current, non-ideal input circuitry. To record usable data, a mitigation strategy was developed, which should allow recovering at least a fraction of the recorded scintillator hits and suppress the multi-counting of events.
\newline The simplest method to suppress the secondary hits without modification of the electronic hardware itself, is to apply a dead time $t_\text{dead}$ to each individual \ac{SiPM} channel. As discussed above, the \ac{FPGA} readout firmware offers the possibility to apply this dead time "online" (sec.\ \ref{sec:DTData-CellHits-DeadTime}). This is expected to drastically reduce the \ac{SiPM} hit rate, as the region left of the selected value in the time difference histogram $\Delta T < t_\text{dead}$ is effectively cut away by it. Applying the dead time directly on the \ac{FPGA} therefore reduces the amount of data recorded from the detector, while it is of course also possible to keep all data and apply the dead time later, in the offline analysis.
\newline With the dead time, one does not only cut away the prompt secondary hits, but also "real" muon events which can of course also occur in short time distances, as they are randomly distributed. Since the modification of the analog circuit was not feasible in the given time frame, the introduction is however the simplest and most effective solution to record usable data in this thesis.

\section{Scintillator strip coincidences}
\label{sec:ScintData-Strips}
Because the raw \ac{SiPM} hits are significantly contaminated with thermal noise, they should not directly be considered as "muon candidate" hits. Instead, coincidences of the two \acp{SiPM} mounted to the same scintillator strip should be evaluated.
\FloatBarrier
\subsection{Strip coincidence evaluation}
\label{sec:ScintData-Strips-Coincidence}
\FloatBarrier
\paragraph{SiPM hit grouping}
First, the hits of all \ac{SiPM} channels are sorted in time. Then a grouping algorithm is applied to the data, which groups all hits together which lie in a specified time window relative to each other:
\begin{equation}
    \Delta T_\text{SiPM group,max} = \max \left\{ \left | T_{i} - T_{j} \right | ; \; i,j=0,...,N_\text{SiPM hits} \right\} \leq \SI{78}{\nano\second}.
    \label{eq:ScintData-Grouping-TimeWindow}
\end{equation}
A time window of $\Delta T_\text{SiPM group,max}=\SI{78}{\nano\second}$ (\SI{100}{\tu}) is selected. This value is smaller than the applied dead time, to avoid multiple hits of the same \ac{SiPM} in one group. In total, there are \num{43315460} \ac{SiPM} hit groups created with this algorithm. Fig.\ \ref{fig:ScintData-Full-Hist-Nhits} presents the number of hits originating from different \acp{SiPM} in the calculated groups.
\begin{SCfigure}[50][htb]
    \centering
    \includegraphics[width=0.49\textwidth]{large_combined_data_plots/53_comb__RAW_SCINT_GROUPS_HIST_n_hits.pdf}
    \caption{Histogram of the number of \ac{SiPM} hits in the created groups.}
    \label{fig:ScintData-Full-Hist-Nhits}
\end{SCfigure}
\newline The majority of groups only contains one hit, which corresponds to a single thermal noise event.\footnote{In principle, it would also be possible that only one \ac{SiPM} would be hit by a muon event due to inefficiencies.} The groups with two hits have an occupancy which is around $10\%$ of the number of groups with one hit. Higher hit numbers are suppressed by at least another order of magnitude.
\FloatBarrier
\paragraph{Isolated coincidence criterion}
The created hit groups are analyzed for coincidences of the two \acp{SiPM} of the same strip. In principle, it would be possible to accept all coincidences which are possible in each group. However, only isolated coincidences in each of the two scintillator layers are considered here, meaning one requires exactly two \acp{SiPM} per layer being hit in a defined coincidence window. The time difference between the \ac{SiPM} hits is defined as
\begin{equation}
    \Delta T_\text{SiPMs} = T_\text{SiPM,0} - T_\text{SiPM,1}.
\end{equation}
The coincidence window is chosen to be $\left| \Delta T_\text{SiPMs} \right| \leq \Delta T_\text{SiPMs,max} = \SI{25}{\nano\second}$ (\SI{32}{\tu}), which should be large enough to cover the maximum expected deviation between input channels after the timing calibration (which corresponds to the granularity of the delay module of \SI{6.25}{\nano\second}, cf.\ sec.\ \ref{sec:ScintData-TimingBias}). As timestamp $T$ of the coincidence hit, the average hit timestamp of the \ac{SiPM} hit timestamps $T_{\text{SiPM},i}$ is selected.
\FloatBarrier
\paragraph{Coincidence time difference}
Fig.\ \ref{fig:ScintData-Full-Hist-DeltaTSiPMs} presents the hit time difference of the two \acp{SiPM} of one scintillator, individually for each strip, plotted in the allowed coincidence range $\Delta T_\text{SiPMs} \in [-\Delta T_\text{SiPMs,max},\; \Delta T_\text{SiPMs,max}]$. In theory, one would expect a single peak around zero in each plot, as one naively expects the \acp{SiPM} to be hit by a photon from the scintillator strip at approximately the same time.
\begin{figure}[htb]
    \centering %% VALUES: WITH FULL DATASET
    \includegraphics[width=\textwidth]{large_combined_data_plots/SCINT_HITS_SPECIFIC_DELTA-TS_SIGNED_SEPARATE.pdf}
    \caption{Histograms of coincidence time difference between \ac{SiPM} hits $\Delta T_\text{SiPMs}=T_\text{SiPM 0}-T_\text{SiPM 1}$, plotted separately for all scintillator strips.}
    \label{fig:ScintData-Full-Hist-DeltaTSiPMs}
\end{figure}
\newline The first observation is that there are two strips which do not show any coincidence events. These dead strips will be discussed in the following section (sec.\ \ref{sec:ScintData-Strips-Results}). For the other strips, non-zero event counts are visible.
\newline  It is clear that there exists a time offset on the $x$-axis between the different strips. This offset is a result of the performed timing calibration: As one can only correct for timing offsets in steps of \SI{6.25}{\nano\second} with the delay module (secs.\ \ref{sec:Scint-ReadoutFirmware-ProgrammableDelays} and \ref{sec:ScintData-TimingBias}), the timing of both \acs{SiPM} is expected to not be completely synchronous. This leads to the observed offset in the coincidence time difference plots.
\newline Apart from the timing offset, the most notable observation is the double-peak structure, which stands in conflict with the expectation of a single peak. The second peak is usually of similar or smaller amplitude as the first peak and the distance of the peak is around \SI{8}{\nano\second}, similar for all strips. The origin of this double-peak structure is initially unclear.
\newline As already discussed above in sec.\ \ref{sec:ScintData-Hits-Systematics}, secondary hits might occur after the initial \ac{SiPM} signal. This might be due to a signal reflection or a \ac{SiPM} after-pulse event. Note that as there is a dead time is applied to all individual channels, the double-peak observed in the histogram must originate from individual events, and it is not possible that the second peak originates of secondary hits within the same event. The only exception would therefore be that the initial hit signal is not properly detected, and the secondary hit is counted wrongly as the initial hit. However, it seems unlikely that this happens in as many cases as would be needed to generate a similar amplitude for the first peak and the second peak in the histogram.
\newline The next possibility would be the optical propagation times, which may vary between different intersection positions of the muon in the scintillator strip. The strip has a length of \SI{50}{\centi\meter}, which yields a maximum possible time difference due to photon propagation time of around \SI{1.7}{\nano\second}, assuming the speed of light in the vacuum. Of course one has to respect the lower speed of light in the medium as well as reflections in the optical path, which might slightly increase the propagation time. This might explain in part the width of the coincidence time distribution in general, but not the double-peak structure, as it is not clear why the light collection would be less efficient if the photon origin is at the center of the scintillator tile.
\newline The hit time digitization in the \ac{FPGA} is implemented with a deserializer (sec.\ \ref{sec:Scint-ReadoutFirmware-SamplingTDC}), which performs a conversion with a granularity of \SI{0.78}{\nano\second} in intervals of \SI{6.25}{\nano\second} (\SI{8}{\tu}). A curious observation is the fact that the distance of the observed peaks ($\approx \SI{8}{\nano\second}$) is approximately the same as this \ac{TDC} conversion interval. This might lead to the hypothesis that the two are related. Indeed, a random bit flip of the timestamp bit above the \ac{TDC} value could explain the discrete time shift. However, if this effect would be present, it should have been noticed already during the testpulse run (sec.\ \ref{sec:ScintData-TimingBias}). The timing histogram of the testpulse however does not show such double-peaks, but a sharp testpulse timestamp. Therefore, a connection of the double-peak structure to the time digitization in the \ac{FPGA} firmware also seems unlikely.
\newline Lastly, it should be noted that the two \acp{SiPM} signals, from which the coincidence is created, are sampled by two different readout boards, as can be seen in tab.\ \ref{tab:Scint-ReadoutBoard-Channels} in the appendix. It could therefore be imagined that small discrete changes in the timing synchronization between the two readout boards might lead to such a double peak structure in the time difference between the two sampled \acp{SiPM}. However, such jumps should also have been observable already in the testpulse run, and the suggested origin is consequently considered as very unlikely.
\newline In summary, the origin of the observed double-peak structure could not be determined with the conducted measurements. Due to the limited available time to record measurements for this thesis, no further characterization measurements with the scintillator were possible. However, it is clear that these measurements should be conducted in the future, to resolve the question of the origin of the observed coincidence time structure. In this thesis, the observed time structure is accepted, and it is continued with all found coincidences, i.e.\ both peaks in the timing histogram considered as valid.

\paragraph{Comparison with cosmic rate}
Finally, the obtained rate of scintillator hits should be briefly compared to the expectation from atmospheric muons. It is clear that the observed variation of the rates between different strips is not expected from cosmics, as already discussed. This should however not be the topic of this section, but rather the comparison of the mean strip rate with an expected rate. This rate is determined again from simulation of tracks in the custom analysis framework. From the propagation of the generated muon tracks (with \ac{MC} method) through the scintillator geometry, the expected hits are calculated. Details on the principle and the assumptions of simulation can be found in appendix \ref{sec:Simulation}.
\newline For one scintillator strip, the simulation yields an average expected rate of $(2.155 \pm 0.008)\;\si{\hertz}$ (tab.\ \ref{tab:Simulation-StripRates}). This expected rate is around a factor four larger than what is observed on average for the strips. As the simulation does not consider the scintillator efficiency, it is clear that a smaller rate in the real experiment is not unexpected. The strip efficiency was not explicitly measured, however a rate of $70-90\%$ should be a plausible assumption. This is not enough to explain the factor four between data and expectation. Additionally, the applied dead time cuts away all signal events which lie close to each other. Because of the exponential distribution of the time difference occurrences, it is clear that a some events are definitely lost. As discussed above, noise hits lead to an artificial extension of the dead time, which leads to the loss of some more data events. Even though the rate observed in data is smaller than in the simulation, it still lies in the same order of magnitude of $\mathcal{O}(\SI{1}{\hertz})$.
\FloarBarrier
\paragraph{Conclusion}
The scintillator hit rate is observed to vary significantly between strips, and the average event rate is lower than the expectation from cosmic muons, however it is still in the same order of magnitude. Problems with the analog readout circuitry have led to the need to introduce a dead time in the \ac{SiPM} data to record measurements of reasonable data size. This has the consequence of biasing the recorded data and can potentially be blamed for the fluctuations between strip rates. The coincidence evaluation of the two \acp{SiPM} of each strip has revealed an unexpected double-peak timing structure. Its origin remains unclear, although a relation to the analog circuitry, the dead time or synchronization problems in the readout system might be possible ideas. However, none of these hypotheses can be accepted with the measured data and analysis strategy. The in-depth analysis and understanding of the analog and sampling part of the scintillator readout system remains an open task after this thesis, which was started with the observations presented above, but could unfortunately not be included within the given time frame. To record usable data for the next chapter (sec.\ \ref{sec:Combined}) to illustrate the synchronization between the scintillator and the \ac{DT} chamber, the recorded scintillator data is used as it is in the current state.
